# Username como login — Plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans, tarefa por tarefa. Passos com checkbox (`- [ ]`).

**Objetivo:** cada conta tem um username único; o login passa a ser username + senha; contas antigas ganham o username automaticamente.

**Arquitetura:** VO `Username` e a derivação a partir do e-mail ficam no domínio de `identity`. O caso de uso `assign_missing_usernames` roda no boot (lifespan) e é idempotente. As rotas de auth trocam `email` por `username` no login. O frontend ajusta cadastro, login, Conta e admin.

**Stack:** FastAPI, pymongo async, pytest-bdd (pt), React + TanStack Query + Vitest, Playwright-bdd.

**Spec:** `docs/superpowers/specs/2026-11-20-username-design.md`

## Restrições globais
- Username: 3–30 caracteres, `[a-z0-9._-]`; entrada normalizada com `strip().lower()`; único (índice único `username_unique`).
- Login: `{username, password}`; erro genérico **"Username ou senha inválidos."**; custo de tempo igual exista ou não (hash dummy, como hoje).
- Username em uso: 409 `USERNAME_TAKEN` **"Este username já está em uso."**; inválido: 422 com a regra.
- Rate limit do login: chaves `ip:<ip>` e `username:<username normalizado>`.
- E-mail continua obrigatório no cadastro e continua definindo o admin.
- Aviso na tela de login (texto exato): **"Agora o login é por username: o seu é a parte do e-mail antes do @ (você pode trocar na página Conta)."**
- Sem commits até o usuário pedir.

## Foco da revisão
1. Duas contas antigas `jose@a.com` e `jose@b.com` → a mais antiga fica `jose`, a outra `jose-2`; rodar a migração de novo não muda nada. Teste na Tarefa 2.
2. Parte local estranha (`a+b@x`, `x@x`, `ÁNGELA@x`, 40 caracteres) → username válido pela regra. Teste na Tarefa 1.
3. Trocar para o próprio username atual com maiúsculas (`Jose` → `jose`) → aceita sem 409. Teste na Tarefa 3.
4. Corrida: dois cadastros com o mesmo username → um 201, outro 409 (índice único, não 500). Teste de contrato na Tarefa 2.
5. Login com username em maiúsculas/espaços (`" Jose "`) → entra. Teste na Tarefa 3.

### Tarefa 1: `Username` e derivação a partir do e-mail (domínio)

**Arquivos:** modificar `backend/src/developer_myself/identity/domain/model.py`; teste `backend/tests/unit/test_username.py`

**Interfaces — produz:**
- `class InvalidUsernameError(IdentityError)`; `class UsernameTakenError(IdentityError)` (mensagem "Este username já está em uso.")
- `@dataclass(frozen=True) Username(value: str)` — normaliza `strip().lower()`; valida `^[a-z0-9._-]{3,30}$`, senão `InvalidUsernameError("Use de 3 a 30 caracteres: letras minúsculas, números, ponto, _ ou -.")`
- `username_from_email(email: Email, taken: Callable[[str], bool]) -> Username` — parte local, minúscula, cada caractere fora de `[a-z0-9._-]` → `_`, corta em 30; se < 3 → base + `-1`; se `taken(candidato)` → `base-2`, `base-3`… cortando a base para caber em 30.

- [ ] **Passo 1: testes que falham**
  - `Username(" Jose ")` == `Username("jose")`; `"ab"`, `"a"*31`, `"jo se"`, `"josé"` → `InvalidUsernameError`
  - `username_from_email(Email("jose.silva+app@x.com"), never)` == `"jose.silva_app"`
  - `Email("ÁNGELA@x.com")` → `"_ngela"`; `Email("x@x.com")` → `"x-1"`; parte local de 40 `a` → 30 `a`
  - com `taken` devolvendo True para `"jose"` e `"jose-2"` → `"jose-3"`; base de 30 caracteres com colisão → resultado com ≤ 30 e terminado em `-2`
- [ ] **Passo 2:** `poetry run pytest tests/unit/test_username.py -q` → falha (import).

### Tarefa 2: Persistência e migração no boot

**Arquivos:** `identity/domain/model.py` (`User.username: Username | None = None` — `None` só em documento antigo antes da migração), `identity/application/ports.py`, repositórios memória/Mongo, `identity/application/use_cases.py`, `shared/adapters/mongo_setup.py` (schema: `username` string ≤ 30 opcional; índice `username_unique` **único e parcial** `{username: {$type: "string"}}` para os documentos antigos sem o campo), `bootstrap.py` (lifespan chama a migração antes do aviso de admin); testes `backend/tests/integration/test_user_repository_contract.py` (ampliar), `backend/tests/features/username.feature` + `test_username.py`

**Interfaces — produz:**
- `UserRepository.get_by_username(username: Username) -> User | None`
- `UserRepository.without_username() -> list[User]` (mais antigos primeiro)
- `UserRepository.set_username(user_id: UserId, username: Username) -> None` — levanta `UsernameTakenError` se outro usuário já tem

- `IdentityUseCases.assign_missing_usernames() -> int` (quantos preencheu)
